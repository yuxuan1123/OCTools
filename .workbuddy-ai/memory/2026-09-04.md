## 悬浮窗拖动"难移动"修复（grabMouse + 光标轮询保护）

现象：标题区已能拖动，但拖动不跟手、易中断，体感"难移动"。

根因（实现问题，非缩放判断）：
- `CustomTitleBar` 拖动时 `mousePressEvent` 设 `_drag_pos` 后**没有 `grabMouse()`**。
  Qt 默认鼠标移动事件只发往光标当前所在的 widget；拖动中鼠标移出标题栏进入
  body（`_Pane`）时，移动事件改发 body，标题栏 `mouseMoveEvent` 收不到 → 窗口停止跟随。
  必须贴着标题栏窄条慢慢拖才不中断。
- 叠加：标题栏高 `overlay_titlebar_h`(默认34) 中 `top_resize_margin`(14) 留给顶边缩放，
  可拖带仅 ~20px，加剧"难命中"。
- resizer 的 `_poll_cursor` 每 20ms 轮询改光标，拖动经过顶边缩放带时光标闪成拉伸箭头，干扰。

改动：
- `titlebar_component.py`：`mousePressEvent` 设 `_drag_pos` 后 `self.grabMouse()`；
  `mouseReleaseEvent` 里 `if self._drag_pos is not None: self.releaseMouse()`。
- `window_resizer.py`：`_poll_cursor` 开头加 `if self._win.mouseGrabber() is not None: return`
  （拖动/缩放有鼠标捕获时暂停轮询，避免覆盖光标/闪烁）。

验证：扩展 `tests/test_overlay_resize.py` 加 [6]「拖动跟手：grab→移动→释放」
（断言 `QWidget.mouseGrabber() is tb`、窗口随 move 改变、release 后解除）。
全套现 `test_overlay_resize` 7/7、`test_window_ctl` 8/8、`test_overlay_title_blank` 1/1，共 16 项全过。

现状：悬浮窗标题栏拖动跟手，鼠标移出标题栏不中断。

## split_titlebar.py / titlebar_split_h.py 直跑 Bootstrap 模式

需求：`split_titlebar.py` 直接 `python ui/ui_component/split_titlebar.py` 跑会
因为 `from .split_window import _Pane` 等**相对 import** 在 `__name__ == "__main__"`
（无包上下文）时报
`ImportError: attempted relative import with no known parent package`；
要求只改 `if __name__ == "__main__": main()` 让它直跑工作。

**模式**（已用于 `split_titlebar.py` 和 `titlebar_split_h.py`）：
- 把 `if __name__ == "__main__":` 块从文件底部挪到**顶部**（在所有 import 之前）。
- 块内用 `importlib.util.spec_from_file_location` 以包成员身份重新加载本文件，
  再 `sys.exit(_mod.main())`。
- 块内 `__name__` 改为包路径（`ui.ui_component.<file>`），重执行时再次遇到同一 if
  块不再触发（条件 False），无递归。

```python
if __name__ == "__main__":
    import os, sys, importlib.util
    _PROJ_ROOT = os.path.normpath(
        os.path.join(os.path.dirname(os.path.abspath(__file__)), "..", "..")
    )
    if _PROJ_ROOT not in sys.path:
        sys.path.insert(0, _PROJ_ROOT)
    _SPEC = importlib.util.spec_from_file_location(
        "ui.ui_component.<file>",
        os.path.abspath(__file__),
    )
    _MOD = importlib.util.module_from_spec(_SPEC)
    sys.modules["ui.ui_component.<file>"] = _MOD
    _SPEC.loader.exec_module(_MOD)
    sys.exit(_MOD.main())
```

**为什么不用 runpy**：`python -m` 时模块已加载在 `sys.modules["ui.ui_component.<file>"]`，
runpy 复用现有模块不重执行 → 此时模块体只跑到 if 块就暂停 → `_ns["main"]` KeyError。
importlib.exec_module 强制重执行（生成新模块对象）能绕过。

```
§3) 创建悬浮框（调用 _create_overlay；内部分 § 1-§ 4 步骤仍由 _create_overlay 内部做）
§4) 接 overlay 应用专属信号（子类 _install_overlay_signals 返回 {signal: cb} 映射）
§5) 创建额外非悬浮组件（子类 _install_extra_widgets 返回 [widget, ...]）
§6) 创建 worker（子类 _make_worker 工厂）
§7) 启动 worker.start(rect)
§8) 立即触发（子类 _kick_off：一次性图像类的首次 _run_once）
§9) 显示 + show_near + set_status + log_started
```

`stop()` 反向清理：早退（未启动）→ worker.stop() → set_region_box(None) →
关闭 extras → _close_overlay()。

### 修复的关键坑（重新发现）

`_close_overlay()` 内**不能**调 `self._overlay.close()` —— `FloatingOverlay.closeEvent`
会 emit `close_clicked` → 同步递归触发 `self.stop()` → 第二次 stop 进清理 → 把
`self._overlay` 提前置 None → 第一次 stop 回到 `deleteLater()` 行 → `None.deleteLater`
→ `AttributeError`。

修复：`_close_overlay` 改为直接 `deleteLater` + 置 None，不调 `close()`。`closeEvent`
自身仍能正常 emit（用户点关闭按钮 / ESC 等）→ 触发 `self.stop()` → 同一清理路径。

### 分类说明（图像类 vs 语音类）

按 `REQUIRES_REGION` 分流：
- **图像类**（screen_ocr / one_shot / realtime）：§2 调 `_resolve_region` 框选或读固定
  截图框；`_capture_excluding()` 在 `_run_once` / `_on_frame` 内做截图。
- **语音类**（subtitle / speech_translate）：§2 跳过（无识别区域）；worker 是
  `BuiltinSpeechRecognize` / `RealtimeSpeechTranslate`，无截图能力。

按 `USE_TRANSLATE` 分流：
- 一次性图像类的 `_run_once` 调 `_thread_ocr(img, use_translate=self.USE_TRANSLATE)`
  → 屏幕 OCR 用 False，一次性翻译用 True。语音类该字段无效。

按 `BUTTONS` 子集决定 `_install_overlay_signals` 应包含哪些信号：

| 按钮 | 信号 |
|---|---|
| retry | retry_clicked → `self._run_once`（基类复用，仅一次性图像类） |
| pause | pause_toggled → `self._on_pause`（worker.set_paused） |
| manual | manual_clicked → `self._on_manual`（worker.capture_now，仅实时翻译） |
| mode | 不需要 hook（base `_create_overlay` 第 §3 步已接 mode_changed 持久化） |
| copy / pin / close | 不需要 hook（base `_create_overlay` 第 §2 步已接 close；copy/pin 在 overlay 内部处理） |

### 遗留风险 / 主动告知

1. **`TranslateAppBase.__init__` 状态字段扩展**：新增 `self._worker` 与 `self._extras`。
   老代码若有 `hasattr(inst, '_worker')` 之类的访问会出问题（之前 `inst._worker`
   不存在）。目前代码内没有这种访问，全套回归已覆盖，**暂无影响**；下次有需求时
   再起条目排查。
2. **`stop()` 幂等**：已加 `is_running()` 早退，但 `_close_overlay` 内 `self._overlay`
   已早一步置 None 后还会被 `deleteLater()`——已用 "先取 `ov = self._overlay`，再
   `self._overlay = None`，再 `ov.deleteLater()`" 修过一次重入坑，**已稳**。
3. **基类不再支持"子类重写 start() 子集"**：现在 `start()` 完全在基类，子类想插入
   步骤必须改 `_make_worker` / `_install_*` 钩子。如果未来有应用需要完全自定义启动
   流程（例如离线初始化 + 网络握手），要考虑加 `_before_start` / `_after_start` 钩子。
