# 外部插件系统（子进程隔离）实现计划

## 一、概述

在 OCTools 中实现「主进程 + 多子进程」的外部插件系统：

- 每个插件运行在独立子进程中，使用自己的 Python 解释器与依赖目录 `deps/<plugin_id>/`，实现依赖/进程完全隔离。

- 主进程通过 stdin/stdout **JSON Lines** 协议与插件通信（请求-响应 / 事件推送 / 心跳 / 关闭）。

- 支持三种加载模式：`always`（常驻）、`lazy`（首次调用时启动）、`auto_recycle`（闲置自动回收）。

- 包含依赖安装（uv，缺失时回退 pip）、心跳监控、崩溃自动重启（最多 3 次）、加载模式切换。

- UI 集成进现有「插件」tab（`tab_plugin.py`），新增「外部插件」管理区。

MVP 覆盖用户指定检查点：依赖隔离（两个插件不同 numpy 版本共存）、崩溃自动重启、心跳超时、模式切换、退出清理、无 uv 环境可运行。

## 四、详细设计（文件级）

### 4.1 `services/ext_plugins/paths.py`（新增）

纯标准库，集中路径常量：

- `app_root()`：`sys.frozen` 时 `dirname(sys.executable)`，否则项目根。

- `plugins_dir()`：`<root>/plugins`

- `deps_dir()`：`<root>/deps`

- `logs_dir()`：`<root>/logs`

- `config_file()`：`<root>/config.json`

- `plugin_source_dir(id)`、`plugin_deps_dir(id)`、`embedded_python_dir()`、`uv_exe()`（`<root>/uv.exe`，非 Windows 时 `uv`）

- `install_log(id)` / `crash_log(id)` / `plugin_log(id)` / `app_log()`

- `ensure_dirs()`：创建 plugins / deps / logs

### 4.2 `services/ext_plugins/detection.py`（新增）

- `find_python()`：优先 `embedded_python/python.exe`（含 linux/mac 变体），不存在则回退 `sys.executable`（开发模式），打印提示。

- `find_uv()`：优先 `<root>/uv.exe`，其次 `shutil.which("uv")`；都无则返回 None（installer 回退 pip）。

- `PluginSource` dataclass：`plugin_id`、`dir`、`main_py`、`requirements`、`has_requirements`。

- `scan_plugins()`：遍历 `plugins/` 子目录，校验 `main.py` + `requirements.txt` 均存在（缺任一 → 跳过并记警告日志），返回 `dict[str, PluginSource]`。

### 4.3 `services/ext_plugins/config_store.py`（新增）

config.json 结构：

```json
{
  "settings": { "idle_timeout_min": 10 },
  "plugins": {
    "demo_hello": { "enabled": true, "load_mode": "lazy" }
  }
}
```

- `load_config()`：缺失/损坏时回退默认；合并 `settings` 默认值。

- `save_config(cfg)`：原子写入（临时文件 + replace），UTF-8、indent=2。

- `plugin_entry(cfg, id)`：不存在时返回默认 `{"enabled": true, "load_mode": "lazy"}`（新插件默认启用、懒加载，不写回直到用户操作）。

- `set_load_mode(cfg, id, mode)` / `set_enabled(cfg, id, enabled)`：校验合法值后写回。

### 4.4 `services/ext_plugins/log_store.py`（新增）

- `app_logger()`：模块级 logger，`RotatingFileHandler(app.log, maxBytes=10MB, backupCount=5)`。

- `append_line(path, text)`：追加写日志文件（UTF-8）。

- 提供 `install_log(id)`、`crash_log(id)`、`plugin_log(id)` 路径（见 paths.py）。

### 4.5 `services/ext_plugins/ipc.py`（新增）

`JsonLinesIpc`：JSON Lines 协议核心（线程安全）。

- 字段：`_write_lock`、`_pending: dict[int, (deadline, callback)]`、`_seq`。

- `send_request(method, params=None, callback=None, timeout=30.0) -> int`：登记 pending + 写 `{"id":N,"method":..,"params":..}\n`。

- `send_event(event, data=None)`：写 `{"event":..,"data":..}\n`。

- `send_ping()`：写 `{"ping": true}`；`send_shutdown()`：写 `{"shutdown": true}`。

- `read_loop()`（读线程目标）：`for line in proc.stdout`：

  - `{"pong": true}` → 调 `on_pong()`

  - `{"event":..}` → 调 `on_event(msg)`

  - `{"id":N, "result"/"error":..}` → 从 `_pending` 取出回调并调用（过期丢弃）

  - 其余忽略

- `_write(obj)`：加锁 `print(json.dumps(obj), flush=True)` 到 stdin（失败/EPIPE 置 `_broken` 标志）。

### 4.6 `services/ext_plugins/process.py`（新增）

`PluginProcess(QObject)`：单个插件子进程生命周期。

- 信号：`ipc_event = Signal(str, object)`（"response"/"event"）、`exited = Signal(str, int)`（插件 id, 退出码）、`log_line = Signal(str, str)`（stderr 文本）、`pong = Signal(str)`。

- `start(python_exe, plugin_id, main_py, deps_dir, cwd, home)` -> bool：

  - 环境变量：`PYTHONPATH=deps_dir`（追加原有，`os.pathsep` 分隔）、`PLUGIN_ID`、`MYAPP_HOME`、`PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`。

  - `subprocess.Popen([python_exe, main_py], stdin=PIPE, stdout=PIPE, stderr=PIPE, text=True, encoding="utf-8", errors="replace", bufsize=1, env=env, cwd=cwd, creationflags=CREATE_NO_WINDOW)`（Windows）。

  - 启动 2 个读线程（stdout → JsonLinesIpc.read\_loop；stderr → 发 `log_line`）；`proc.wait()` 线程结束后发 `exited`。

  - 记录 `last_pong`、`last_active`（收到任何消息即刷新）。

- `send_request(method, params=None, callback=None)`、`send_event(...)`、`ping()`、`shutdown()`（发 `{"shutdown":true}`）。

- `alive()`：`poll()` is None。

- `kill_tree(grace=0)`：`psutil.Process(pid)` + `children(recursive=True)` 全部 kill（grace 内先尝试 terminate）。

- `mark_pong()`：刷新 `last_pong`（读线程回调）。

### 4.7 `services/ext_plugins/installer.py`（新增）

`InstallWorker(QObject)`，moveToThread 到管理器持有的 `QThread`，串行处理队列。

- 信号：`install_requested = Signal(str)`、`progress = Signal(str, int, str)`（id, percent(-1 为不确定), 行文本）、`finished = Signal(str, bool, str)`。

- `_do_install(plugin_id)`（工作线程执行）：

  - requirements 为空/不存在 → 直接 `finished(id, True, "无依赖")`。

  - 命令：有 uv → `[uv, pip, install, --python, python_exe, --target, deps_dir, -r, req]`；无 uv → `[python_exe, -m, pip, install, --target, deps_dir, -r, req]`。

  - Popen 合并 stdout/stderr，逐行 emit `progress(id, -1, line)` 并追加到 `logs/install_<id>.log`。

  - 退出码 0 → `finished(id, True, "安装完成")`；非 0 → `finished(id, False, "安装失败，详情见 logs/install_<id>.log")`，并记录日志。

- 串行化：manager 在收到 `finished` 后取队首继续 emit `install_requested`。

### 4.8 `services/ext_plugins/manager.py`（新增，核心）

`PluginManager(QObject)` + 单例 `instance()`。

**状态常量**：`MISSING / NEEDS_INSTALL / INSTALLING / INSTALL_FAILED / READY / STARTING / RUNNING / STOPPING / CRASHED / DISABLED`。

**信号**：

```
plugins_scanned      = Signal(dict)            # {plugin_id: PluginInfo}
plugin_state_changed = Signal(str, str)        # (plugin_id, state)
install_progress     = Signal(str, int, str)
install_finished     = Signal(str, bool, str)
call_result          = Signal(str, bool, str)  # (plugin_id, ok, message)
log_updated          = Signal(str, str)        # (plugin_id, kind: run/install/crash)
```

**PluginInfo dataclass**：`plugin_id / dir / main_py / requirements / deps_dir / has_deps / enabled / load_mode / state / last_log`。

**数据结构**：`_sources`（扫描结果）、`_infos`、`_processes: dict[str, PluginProcess]`、`_retries: dict[str, int]`、`_alive_since`、`_last_active`、`_stopping: set`、`_pending_calls: dict[str, tuple]`、`_install_queue: list`。

**定时器**（QTimer）：

- 心跳：每 5s 对所有 RUNNING 进程 `ping()`；若 `now - last_pong > 12s`（连续两次无响应）→ 记 crash 日志、`kill_tree`、按崩溃重启流程处理。

- 闲置回收：每 60s 检查 `auto_recycle` 且 RUNNING 的插件，`now - last_active > idle_timeout_min*60s` → 发 shutdown 并标记回收（下次调用时懒启动）。

**核心方法**：

- `start()`：幂等；`ensure_dirs()` → `scan()` → `load_config()` → emit `plugins_scanned` → 对 enabled 且 `has_deps=False` 的插件入安装队列 → 对 enabled 且 deps 就绪的按模式启动（always/auto\_recycle 立即启动，lazy 不启动）。启动安装线程与两个定时器。

- `scan() -> dict[str, PluginInfo]`：合并扫描结果与配置，计算状态（MISSING / NEEDS\_INSTALL / READY）。

- `install(plugin_id)`：入队（INSTALLING 状态 + `install_progress` 信号）。

- `enable(plugin_id)`：置 enabled=True 存配置；deps 缺失先入安装队列，装完自动按模式启动；否则按模式启动。

- `disable(plugin_id)`：置 enabled=False 存配置；进程存在 → STOPPING → shutdown → 等 3s → `kill_tree` → 状态 DISABLED。

- `set_load_mode(plugin_id, mode)`：按规范 7.6 处理进程过渡（always/auto\_recycle→lazy 关进程；lazy→always/auto\_recycle 立即启动；always↔auto\_recycle 只改计时器），存配置。

- `call(plugin_id, method, params=None)`：进程未运行 → 记 `_pending_calls` 并按 lazy 启动；运行中 → 直接 `send_request`，响应/错误 → emit `call_result`。收到任何消息刷新 `_last_active`。

- `test_crash(plugin_id)`：`call(plugin_id, "crash")`（演示崩溃恢复）。

- `_on_process_exited(plugin_id, code)`：预期停止（`_stopping` 中）→ 状态 READY/DISABLED；否则 → 记 crash 日志 → 存活>60s 重置重试计数 → `_retries < 3` 则 2s 后重启（STARTING→RUNNING），否则状态 CRASHED（不再自动重启）。

- `shutdown()`：停定时器；对所有存活进程发 shutdown，轮询等待 ≤5s，剩余 `kill_tree`；退出安装线程。

**UI 调用入口**：`PluginManager.instance()`，`MainApp` 构造时 `start()`，`app.aboutToQuit` 时 `shutdown()`。

## 五、关键流程要点

- **IPC 协议**：请求 `{"id":N,"method","params"}`；响应 `{"id":N,"result"|"error"}`；事件 `{"event","data"}`；心跳 `{"ping"|"pong": true}`；关闭 `{"shutdown": true}`。每行一条 JSON + `\n`，stdout 仅写协议数据，stderr 走独立管道（防污染协议流）。

- **依赖安装**：`uv pip install --python <python> --target deps/<id> -r plugins/<id>/requirements.txt`；无 uv 时回退 `python -m pip install --target`。空 requirements 直接跳过。

- **启动**：`[python, plugins/<id>/main.py]`，`PYTHONPATH=deps/<id>`，`cwd=plugins/<id>/`。

- **崩溃/心跳超时**：≤3 次自动重启（间隔 2s）；存活 >60s 重置计数；超限 → CRASHED 停止重启。

- **退出**：全部发 shutdown → 等 ≤5s → 剩余 kill\_tree → 保存配置。

## 六、假设与决策

1. **config.json 放项目根**（按用户规范原文），与 `config/presets/`（应用设置）分离，只存插件列表/启用/模式/闲置阈值。
2. **新插件默认** **`enabled=true, load_mode=lazy`**（安全默认，不自动占资源；用户可改）。
3. **无 uv 时回退 pip 安装**：打包版随附 uv.exe（规范 10.1），开发机无 uv 时用 venv pip 保证可测试；回退时记日志提示。
4. **开发模式 Python 回退** **`sys.executable`**：`embedded_python/` 仅打包环境存在；源码开发直接用当前解释器，安装目标仍是 `deps/<id>/`，隔离逻辑一致。
5. **UI 集成进现有「插件」tab**（复用组件与 CONFIG 参数，不新增 ui\_config.json 配置项）。
6. **外部插件与内置 tab 插件并存**：内置挪到 `plugins/tabs/`（打包模式），根 `plugins/` 归外部插件。
7. **安装串行执行**（uv 输出无法解析精确百分比 → 进度条用不确定模式 + 逐行文本），避免并行安装的资源竞争。
8. **心跳阈值 12s**（两次 5s 心跳无响应），闲置阈值默认 10 分钟（config.json 可调）。

## 七、验证步骤

1. 启动 `python main.py`（会请求管理员权限）→ 打开「插件」tab → 出现「外部插件」区与 3 个演示插件。
2. **无依赖跳过安装**：demo\_hello 直接「就绪」（空 requirements）。
3. **依赖安装 + 隔离检查点**：demo\_numpy\_a / demo\_numpy\_b 显示安装进度条 → 完成后「就绪」；调用测试（echo）或 env 方法，两个插件各自返回 `numpy 2.0.2` / `1.26.4`，互不污染。
4. **模式切换检查点**：lazy→always（进程立即启动，状态运行中）；always→lazy（进程销毁，状态就绪）。
5. **崩溃重启检查点**：点「崩溃测试」→ 状态短暂「启动中」后回到「运行中」（自动重启 ≤3 次）；连续崩溃 4 次 → 状态「已崩溃」不再重启。
6. **心跳超时检查点**：`call("sleep", 15)` → 进程卡死 → 心跳超时 → 强制重启。
7. **auto\_recycle 检查点**：把 config.json `idle_timeout_min` 临时改为 1，模式切 auto\_recycle → 闲置 1 分钟后进程自动回收；再调用时懒启动。
8. **退出清理检查点**：关闭主窗口 → 任务管理器无残留 `python`/`python.exe` 子进程；`logs/crash_*.log`、`install_*.log` 内容正确。
9. **日志**：`logs/app.log` 滚动记录；安装/崩溃日志分文件。
