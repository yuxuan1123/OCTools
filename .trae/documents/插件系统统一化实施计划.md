# 插件系统统一化实施计划

## 一、Context(背景与目标)

当前 OCTools 存在**两套并行插件体系**:

| <br /> | 原始导入插件(tab 插件)                                      | ext\_plugins 外部插件                             |
| ------ | --------------------------------------------------- | --------------------------------------------- |
| 位置     | `ui/tabs/plugins/<name>/` + `manifests/<name>.json` | `plugins/<name>/`(main.py + requirements.txt) |
| 运行     | 主进程 `importlib` 直接导入                                | 独立子进程,JSON Lines IPC                          |
| 依赖     | 仅主进程环境                                              | `deps/<id>/` 独立安装、版本隔离                        |
| 格式     | 文件夹 + JSON manifest + `tab_xxx.py`                  | `main.py` + `requirements.txt`                |

用户诉求:**只有一块插件体系** —— 保留原始导入格式(文件夹 + JSON manifest + `tab_xxx.py`),同时获得依赖隔离能力。UI 呈现按插件依赖自动分流为三种模式(用户已拍板):

1. **direct**:插件用 PySide6 且无额外依赖(requirements 为空)→ 沿用现有 tab 加载:主进程直接 `import 模块 → 取类 → 实例化 QWidget`,无需隔离。
2. **desc**:插件用 PySide6 但有主进程没有/版本不同的库(requirements 非空且无第三方 UI 库)→ 子进程隔离依赖,插件返回**控件树 JSON**,主进程渲染嵌入主窗口。
3. **window**:插件用非 PySide6 UI 库(PyQt5/PyQt6/tkinter 等)→ 子进程隔离依赖,插件自己创建**独立窗口**。

附带要求:

- 内置 4 个 tab 插件(tree/color\_pick/style\_lab/terminal)**迁移为外置插件**,只移动 `tabs/`、`options/` 下的 py 文件;共享层(`services/`、`ui_component/`、`widgets/`、`config/`、`core/`、`toast` 等)留主进程。

- 旧 `main.py` 格式的 demo 插件**迁移到 tab 格式**,删除旧格式兼容。

- UI 描述采用**控件树 JSON**(type + props + children),不限控件集(渲染器按 type 动态创建任意 PySide6 控件)。

## 二、统一后的插件目录结构

```
OCTools/
├── plugins/                          # 统一插件根(内置迁移 + 用户导入 + demo)
│   ├── __init__.py
│   ├── tree/                         # 内置迁移:tab_tree.py, card_*.py, tree_core.py, set_tts.py
│   ├── color_pick/                   # tab_color_pick.py
│   ├── style_lab/                    # tab_style_lab.py
│   ├── terminal/                     # tab_terminal.py
│   ├── demo_numpy_a/                 # tab_numpy_a.py + requirements.txt(numpy==2.0.2)
│   ├── demo_numpy_b/                 # tab_numpy_b.py + requirements.txt(numpy==1.26.4)
│   └── manifests/                    # 所有插件清单 <name>.json
├── deps/<name>/                      # 插件依赖安装目标(仅 desc/window 需要)
├── logs/                             # 日志
├── services/ext_plugins/             # 核心服务(扩展改造)
│   ├── host.py                       # 新增:统一子进程运行时(替代各插件自己的 main.py)
│   └── ...(paths/detection/config_store/log_store/ipc/process/installer/manager)
└── ui/tabs/plugin_ui/                # 新增:主进程侧 desc 渲染
    ├── desc_renderer.py              # 控件树 JSON → PySide6 控件
    └── host_tab.py                   # HostTabWidget:加载 desc 插件的容器 tab
```

manifest 扩展字段(在现有 `name/class_name/module_path/order/settings` 基础上):

```json
{
  "name": "demo_numpy_a",
  "class_name": "TabNumpyA",
  "module_path": "plugins.demo_numpy_a.tab_numpy_a",
  "ui_mode": "desc",
  "order": 100
}
```

- `ui_mode`:`direct` / `desc` / `window`,**由 requirements 自动检测**写入(见 3.1),也可手工指定。

- `requirements`:存于 `<name>/requirements.txt`(与现有 ext\_plugins 一致),**不入 manifest**。

## 三、详细设计(文件级)

### 3.1 模式检测 —— `services/ext_plugins/detection.py`(修改)

新增 `UI_FRAMEWORKS` 集合与 `detect_ui_mode(requirements_text) -> str`:

```python
# 非 PySide6 的第三方 UI 框架(出现即 window 模式)
THIRD_UI = {"pyqt5", "pyqt6", "pyqt", "tkinter", "wxpython", "wx",
            "kivy", "customtkinter", "pysimplegui", "pyside2"}

def detect_ui_mode(req_text: str) -> str:
    pkgs = _parse_package_names(req_text)      # 解析 requirements 包名(忽略版本/行内注释)
    if not pkgs:
        return "direct"                        # 无依赖 → 主进程直接 import
    if any(p in THIRD_UI for p in pkgs):
        return "window"                        # 第三方 UI 库 → 独立窗口
    return "desc"                              # 其他库(PySide6/numpy 等)→ 控件树 JSON + 隔离
```

- `_parse_package_names`:逐行取包名(`strip` 版本号与 `#` 注释),小写归一。

- `scan_plugins()` 改造:不再强校验 `main.py`,改为识别**两种子格式**:

  - tab 格式:目录含 `tab_*.py` + `manifests/<name>.json` → 从 manifest 读 `class_name/module_path/ui_mode`;

  - 旧 main.py 格式:保留短暂兼容,迁移完成后移除(见 3.8)。

- `PluginSource` 增加 `ui_mode` 字段。

### 3.2 统一子进程运行时 —— `services/ext_plugins/host.py`(新增)

替代每个插件自带的 `main.py`。主进程启动命令:`python host.py <plugin_id>`(host.py 与 deps 同目录约定不变)。

职责:

- 读 `manifests/<plugin_id>.json` 与 `requirements.txt`,校验文件存在;

- 按 `ui_mode` 分发:

  - **desc**:`importlib.import_module(module_path)` → `getattr(module, class_name)()` → 实例方法 `describe_ui() -> dict`(控件树 JSON);事件请求 `invoke_action(action, params) -> dict`(返回结果或全量/增量控件树更新)。

  - **window**:实例化后调用 `show()` 创建独立窗口;主进程仅管理生命周期(启动/心跳/关闭),窗口完全由子进程绘制。

  - direct 模式**不启动子进程**(主进程直接 import),host.py 不处理。

- 复用现有 JSON Lines 协议(ipc.py 主进程侧 + 插件侧循环模板),支持 `ping/pong`、`shutdown`、`describe_ui`、`invoke_action` 请求。

插件侧接口约定(desc 模式 `tab_xxx.py`):

```python
class TabNumpyA:
    def describe_ui(self) -> dict:
        return {"type": "VBox", "children": [
            {"type": "QLabel", "props": {"text": f"numpy {numpy.__version__}"}},
        ]}
    def invoke_action(self, action: str, params: dict) -> dict:
        ...  # 返回 {"result": ...} 或 {"update": <控件树增量>}
```

### 3.3 控件树 JSON 协议 —— `ui/tabs/plugin_ui/desc_renderer.py`(新增)

主进程渲染器:递归解析控件树 JSON → 创建 PySide6 控件 → 绑定事件。

```json
{
  "type": "VBox",
  "children": [
    {"type": "QLabel", "props": {"text": "文件名"}},
    {"type": "QPushButton", "props": {"text": "生成", "objectName": "btn_gen"},
     "actions": {"clicked": "generate"}},
    {"type": "QPlainTextEdit", "props": {"objectName": "out", "readOnly": true}}
  ]
}
```

- **布局类型**:`VBox` / `HBox` / `Grid` / `Form` / `Scroll`(QScrollArea 包裹)。

- **控件映射表**(`type` → 工厂):QLabel、QPushButton、QLineEdit、QTextEdit、QPlainTextEdit、QComboBox、QCheckBox、QRadioButton、QSpinBox、QDoubleSpinBox、QSlider、QProgressBar、QListWidget、QTableWidget、QFrame、QGroupBox。`props` 作为构造参数/`set` 属性(`objectName` 必填,用于事件定位)。

- **事件**:`actions` 里 `{"<signal>": "<action_id>"}`;渲染器绑定后,触发时调 `PluginManager.invoke_action(plugin_id, action_id, {"objectName": ..., "value": ...})`,响应若含 `update` 则重建局部控件。

- 复用 `config/ui_config.py` 的 `CONFIG` 取值与 `ui/tabs/tab_component/` 现有卡片/页头构建函数,保证视觉一致。

### 3.4 desc 插件容器 tab —— `ui/tabs/plugin_ui/host_tab.py`(新增)

`HostTabWidget(QWidget)`:作为主窗口右侧内容区容器:

- 首次加载:状态「加载中…」→ `PluginManager.call(pid, "describe_ui")` → 渲染器构建控件 → 嵌入;

- 事件转发:子控件信号 → `PluginManager.call(pid, "invoke_action", ...)` → 应用返回的 `update`;

- 插件崩溃/进程重启时显示「插件异常,正在重启…」并自动重连渲染;

- `closeEvent` 通知 manager 停止(仅 lazy 模式)。

### 3.5 管理服务改造 —— `services/ext_plugins/manager.py`(修改)

- `PluginInfo` 增加 `ui_mode` 字段;

- `scan()` 从 `PluginSource` 透传 `ui_mode`;

- 新增 `invoke_action(plugin_id, action, params) -> None`:内部走 `call(plugin_id, "invoke_action", {...})`,响应经 `call_result` 信号回 UI(desc 渲染器监听);

- `call_result` 已具备 `(plugin_id, ok, message)` 通道,`_handle_response` 需把 result 原样透传(现有实现会 `json.dumps` 成字符串 —— 改为 result 为 dict 时保留结构化数据,供渲染器使用);

- direct 模式插件**不注册**到 manager(不启动子进程),由主进程直接 import(见 3.6)。

### 3.6 主进程加载分流 —— `ui/main_window.py`(修改)

`_get_or_create_widget(class_name, module_path)` 增加 ui\_mode 分支:

```python
mode = manifest_ui_mode(name)   # 从左侧导航信息读取,默认 direct
if mode == "direct":
    ...现有 importlib 逻辑不变...
elif mode == "desc":
    return HostTabWidget(plugin_id, manager)   # 容器,内部异步渲染
elif mode == "window":
    manager.call(plugin_id, "show_window")     # 子进程弹独立窗口
    return placeholder 页面("已打开独立窗口")
```

- `LeftSidebar._scan_tab_infos`([left\_sidebar.py](file:///d:/Project/PythonProject/OCTools/ui/ui_component/left_sidebar.py#L176-L202))读取 manifest 时把 `ui_mode` 一并放入 info;

- `MainApp.__init__` 默认首 tab、`_preimport_all_tabs` 均按 mode 跳过 desc/window 插件的直接 import。

### 3.7 导入流程改造 —— `ui/tabs/tab_plugin.py`(修改)

`_install_plugin()` 在现有复制文件夹 + 写 manifest 基础上:

1. 若用户文件夹含 `requirements.txt` → 一并复制,并调用 `PluginManager.instance().install(name)` 入安装队列(串行,进度复用现有 `ExternalPluginsSection`);
2. 写入 manifest 时根据 requirements 自动计算 `ui_mode`(复用 `detect_ui_mode`),写入 `ui_mode` 字段;
3. 提示文案更新:说明依赖将安装到 `deps/<name>/`,UI 按依赖自动选择加载方式。

### 3.8 旧格式迁移与删除

- **demo 插件迁移**:`plugins/demo_hello/main.py` → `plugins/demo_hello/tab_hello.py`(direct);`demo_numpy_a/b` 的 main.py → `tab_numpy_a.py` / `tab_numpy_b.py`(desc,requirements 保留 numpy 版本)。各目录补 `__init__.py` + `manifests/*.json`。删除旧 `main.py`。

- **内置插件迁移**:复制 `ui/tabs/plugins/{tree,color_pick,style_lab,terminal}` 下的 py 与 `manifests/{...}.json` 到根 `plugins/`;manifest 中 `module_path` 改为 `plugins.<name>.tab_xxx`、增加 `"ui_mode": "direct"`、`"files"` 字段保留。共享层 import(`config.ui_config`、`core.engines`、`ui.tabs.tab_component`、`ui.toast` 等)不改 —— direct 模式下主进程直接加载,共享层天然可用。

- **删除旧目录**:迁移后删除 `ui/tabs/plugins/` 整目录、`ui/tabs/plugin_ext.py` 中针对 main.py 格式的说明与按钮(`调用测试/崩溃测试` 保留给 desc/window 插件,去掉对 main.py 的假设)。

- **plugin\_registry.py**([plugin\_registry.py](file:///d:/Project/PythonProject/OCTools/ui/tabs/plugin_registry.py)):`_plugins_pkg()` 统一为 `plugins`(源码与打包一致),`plugins_dir()` 指向根 `plugins/`,移除 `plugins.tabs` 打包特例。

- **detection.scan\_plugins()**:移除 main.py 强校验,识别 tab 格式 + manifests。

### 3.9 设置页兼容 —— `ui/tabs/tab_settings.py`(修改)

- `_iter_manifests()` 已统一扫描 `iter_manifest_dirs()`,迁移后自动覆盖新位置;

- 设置弹窗 `_open_dialog` 走 `importlib` 导入插件内 `set_*.py` —— **仅 direct 模式可用**(主进程直接 import);desc/window 插件若带 set 设置页,本轮不做(其 UI 在子进程,设置页后续按 `invoke_action` 扩展),manifest 中该类插件的 `settings` 段暂时忽略并在页面提示「设置页仅支持直载插件」。

### 3.10 管理 UI —— `ui/tabs/plugin_ext.py`(修改)

- 卡片增加 `ui_mode` 徽章:直载(灰)/ 隔离渲染(蓝)/ 独立窗口(紫);

- direct 插件卡片显示「主进程直载」,无安装/调用/崩溃按钮;

- desc/window 卡片保留 启用/禁用、加载模式、安装依赖、调用测试(desc)、崩溃测试、日志。

## 四、验证步骤

1. **内置插件直载**:启动 `python main.py` → 左侧导航出现 tree/color\_pick/style\_lab/terminal(从 `plugins/` 加载,direct),点击各 tab 功能正常、样式与迁移前一致(共享层仍在主进程)。
2. **desc 插件隔离**:`plugins/demo_numpy_a/b` 安装依赖后,点击 tab → 主进程渲染控件树,显示各自 `numpy 2.0.2` / `1.26.4`(互不冲突);无依赖 demo 显示 hello。
3. **导入流程**:在「插件」页导入一个带 `requirements.txt`(如 numpy)且含 `tab_*.py` 的文件夹 → 自动判为 desc、自动安装依赖、manifest 写入 ui\_mode;左侧导航出现并可渲染。
4. **window 插件**:导入 requirements 含 `tkinter` 的插件 → ui\_mode=window → 点击后弹出独立窗口;主进程显示占位页。
5. **崩溃/心跳/退出**:desc/window 插件照旧支持心跳(5s/12s)、崩溃重启(≤3 次)、退出清理(≤5s 强杀);smoke 脚本更新为 tab 格式后全绿。
6. **设置页**:tree 等 direct 插件的设置按钮照常弹出(主进程 import 插件内 set\_xxx.py)。

## 五、实施顺序(建议)

1. detection.py:新增 `detect_ui_mode` + `scan_plugins` 改 tab 格式识别;
2. host.py:统一子进程运行时(desc/window);
3. desc\_renderer.py + host\_tab.py:主进程渲染与容器;
4. manager.py:ui\_mode 透传 + invoke\_action + result 结构化;
5. main\_window\.py + left\_sidebar.py:加载分流;
6. tab\_plugin.py:导入流程(requirements 自动检测 + 安装);
7. 内置插件迁移 + demo 迁移 + 删除旧目录 + plugin\_registry 统一;
8. plugin\_ext.py UI 徽章与按钮适配;tab\_settings.py 兼容;
9. 更新 smoke 脚本验证,回归全部检查点。
